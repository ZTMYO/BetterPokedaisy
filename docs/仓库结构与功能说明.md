# PokeDaisy 仓库结构与功能说明

> 生成日期：2026-10-31 · 基于仓库 main 分支（最新提交 52f9597）

## 一、项目概述

**PokeDaisy** 是一款面向 Android 双屏/单屏掌机的 **Game Boy / GBC / GBA / Nintendo DS 模拟器 + 实时游戏伴侣（companion）** 应用，专为宝可梦系列游戏（红 → 黑）及热门 ROM hack 设计。

- 游戏画面旁边运行一个"伴侣"界面，实时读取游戏内存：队伍、背包、地图、战斗克制、图鉴、无剧透攻略等，UI 模仿游戏原生菜单风格。
- 双屏设备（AYN Thor、Retroid Pocket Duo 等）：游戏在上屏、伴侣在下屏；单屏设备：伴侣以悬浮窗/侧边面板呈现，另有 HUD、快捷菜单、战斗按钮。
- 技术栈：**Kotlin + Jetpack Compose（Android 8.0+）**，C/C++ JNI 桥接模拟核心，模拟核心基于 **mGBA**（GB/GBC/GBA）与 **melonDS**（NDS，含自研补丁）。
- 许可证：GPL v3 + 附加署名条款。另有实验性的 3DS 移植和 Linux（SDL2）移植。

## 二、顶层目录结构

```
pokedaisy/
├── app/                  # Android 应用主体（Kotlin + C/C++ JNI）
├── 3ds/                  # Nintendo 3DS 移植（C 语言伴侣核心）
├── linux/                # Linux/SDL2 掌机移植（早期测试，含 portmaster）
├── gamedata/             # 每游戏数据源（TOML），生成各平台代码的唯一事实来源
├── scripts/              # 构建/生成/逆向/校验脚本（Python 为主）
├── ui-preview/           # Compose Desktop 无头 UI 渲染与压力测试
├── native-capture/       # Docker + libmgba 的游戏内截图采集
├── website/              # Astro 静态站点（官网 + 在线手册）
├── third_party/          # git 子模块：mgba、melonds、rcheevos（+ 自研补丁）
├── docs/                 # 开发/发布文档、在线手册源、前端集成说明、设计规格
├── .github/              # CI/CD workflows（Release、check 等）
├── .claude/              # AI 辅助开发配置
├── Makefile              # 全部工作流的便捷入口（make help）
├── PLAN.md / CLAUDE.md   # 项目计划与 AI 协作上下文
├── build.gradle.kts      # Gradle 根配置（单 app 模块）
└── gradle.properties / settings.gradle.kts / gradlew
```

## 三、核心模块说明

### 3.1 `app/` — Android 应用（主交付物）

- **`app/src/main/kotlin/com/pokedaisy/app/`**（约 590 个 Kotlin 文件）：
  - 模拟器引擎：`EmulatorEngine.kt`、`MgbaCore.kt`（mGBA 封装）、`Gen1Loop.kt` / `M4aLoop.kt` / `Gen1MusicRenderer.kt` / `FfMusicPlayer.kt`（智能快进下音乐保持原速的独立渲染）。
  - 输入与控制：`GbaInput.kt`、`GbaControls.kt`、`Controllers.kt`、`Hotkeys.kt`、`TouchControlsView.kt`、`BattleInputController.kt`。
  - 显示与布局：`EmulatorView.kt`、`ScreenShaders.kt`、`WideScreen.kt` / `WideCamera.kt`（宽屏 EXPAND 渲染）、`DualScreenPresentation.kt`、`NdsBottomScreen.kt`、`SidePanel.kt` / `PortraitPanel.kt` / `GameStageLayout.kt`。
  - 游戏库与启动：`LibraryActivity.kt`、`LauncherScreen.kt`、`RomIntake.kt` / `RomIdentity.kt` / `RomSupportRequest.kt`、`CoverArtSync.kt`（SteamGridDB 封面）。
  - 存档：`GameSaves.kt`、`SaveStates.kt`、`SaveBackups.kt`、`SaveEditorActivity.kt`、`SavesLocation.kt`（与 mGBA/RetroArch 共享 `.sav`/`.srm`）。
  - 其他：`cheats/`（金手指）、`achievements/`（RetroAchievements，rcheevos）、`overlay/`（RetroArch overlay）、`SettingsActivity.kt`、`SetupScreen.kt`、`AppUpdater.kt`（应用自更新）、`CrashReports.kt`（Crashlytics，默认关闭）。
- **`companion/`（游戏伴侣）**：
  - `ui/`：PARTY / BAG / BATTLE / MAP / DEX / GUIDE / CARD / STATES / NUZLOCKE 等标签页的 Compose UI。
  - `data/`：游戏内存读取层（含生成的 `NativeConfigsGen.kt`、`GameDataRecordsGen.kt`）。
  - 单功能类：`Nuzlocke.kt`、`SmartFf.kt`、`FlyAction.kt`、`ItemUse.kt`、`StateSlots.kt`、`FieldHudSettings.kt`、`WhatsNew.kt` 等。
  - `i18n/`：英/日/法/德/意/西/葡 七语翻译。
- **`app/src/main/cpp/`（18 个 C/C++ 文件）**：JNI 桥接层
  - `pokedaisy_jni.c`：JNI 入口；`pk_call.c`：游戏函数调用原语。
  - `pk_gb_field.c` / `pk_wide.c` / `pk_wide_gb.c`：内存字段读取与宽屏对象绘制。
  - `pk_rewind.c`：回溯；`pk_cheats.c`：金手指；`pokedaisy_ra.c`：RetroAchievements 接入。
  - `nds/`：melonDS 封装——渲染（`pk_nds_gl.cpp`）、音频（`pk_nds_music.cpp`）、宽屏（`pk_nds_wide.cpp`）、平台适配（`pk_nds_platform.cpp`）等。
- **`app/src/main/assets/`**：像素字体、屏幕 shader（LCD/扫描线/CRT/GBA 配色/xBR 等）。
- **`app/src/test/`**：JVM 单元测试（存档解码夹具、UI 逻辑）+ Paparazzi 截图测试（快照在 `app/src/test/snapshots/`）。

### 3.2 `gamedata/` — 每游戏数据源

- 唯一事实来源：每款游戏的内存地址、偏移、布局以 TOML 描述（53 个 schema + 数据文件）。
- 目录：`gen3/retail/`（火红/叶绿/绿宝石/红蓝宝石）、`gen3/ports/`（其他语言版本）、`gen3/hacks/`（每个 hack 一个文件）、`gen3/records/`（图鉴/攻略/训练师卡等记录）、`schema/`（字段定义）、`targets/3ds.toml`（3DS/Linux 的 C 输出）。
- **运行时零读取**：`scripts/gen_gamedata.py` 把 TOML 编译为 Kotlin（`NativeConfigsGen.kt`）与 C（`pd_configs_gen.h`），产物提交入库；`make gamedata` 重新生成，`--check` 校验新鲜度（CI 必过项）。生成文件禁止手改。

### 3.3 `3ds/` — 3DS 移植

- C 语言实现的伴侣核心（`core/pd_*.c`：canvas/card/dex/game/guide/map/menu/settings/style/snapshot 等），与 Android 共用 gamedata 生成的配置；`make -C 3ds test-configs-gen` 参与 CI。

### 3.4 `linux/` — Linux 移植

- SDL2 + 同一 mGBA 核心 + 3DS 版伴侣，面向 PortMaster 掌机，早期测试阶段；复用 `targets/3ds.toml` 的 C 输出。

### 3.5 `ui-preview/` — 无头 UI 渲染

- Compose Desktop 工程，直接引用 app 的真实 UI 源码（复制 + shim 少量 Android API），无需 Android SDK 即可渲染 PNG（`make preview` → `ui-preview/build/shots/`）。
- `src/render/`：`Stress.kt`（标签快速切换的内存/耗时压力测试）、`DocsShots.kt`（手册截图重渲染）、`DocsSearchCheck.kt` / `KeyedStateCheck.kt`（CI 检查）。

### 3.6 `native-capture/` — 游戏内截图采集

- Docker 镜像（libmgba）对真实 ROM 做无头采集：菜单截图、内存捕获夹具（供单元测试），服务 `capture_fixture.sh` / `screenshot_menus.sh`。

### 3.7 `scripts/` — 工具脚本

- `gen_*.py`：从反编译工程（pret decomps）生成图鉴/攻略/经验/技能/语言表等游戏数据。
- `decomps.py`：对接本地反编译仓库路径（经 `DECOMPS` 环境变量 / `local.mk`）。
- `check_translations.py`：翻译完整性校验；另有宽屏地址查找、存档转换等一次性逆向脚本。

### 3.8 `website/` — 官网

- Astro 7 静态站（`pokedaisy.com`）：文档手册源（`src/pages` / `docs` 同步）、匿名访问计数（`functions/`）、docs-art 生成、`node --test` 文档测试（链接解析、无破折号、每个设置项有文档、搜索用例）。

### 3.9 `docs/` — 文档

- `DEVELOPMENT.md`（构建指南）、`RELEASING.md`（发布流程）、`ROM_FEATURES.md`、
- `manual/`（应用内/在线手册，含截图 `shots/`）、`specs/`（设计规格）、
- `es-de/`、`iisu/`（第三方前端启动器集成）。

## 四、构建、测试与发布

所有入口集中在根 `Makefile`（`make help` 查看）：

| 命令 | 作用 |
|---|---|
| `make submodules` | 首次构建拉取 mGBA / rcheevos / melonDS 子模块 |
| `make apk` / `make install` / `make run` | 构建/安装/启动 debug APK |
| `make gamedata` | 从 `gamedata/` 重新生成各平台代码 |
| `make test` | JVM 单元测试 |
| `make check` | CI 全量：翻译、gamedata 新鲜度、3DS 配置、单测、debug 构建、ui-preview 压力/文档搜索/键控状态、website 测试与构建 |
| `make test-roms ROM_DIR=...` | 用真实合法 ROM 转储跑扩展单测 |
| `make shots` / `make preview` | Paparazzi 快照 / Compose Desktop 渲染 |
| `make docs-shots` / `make docs-check` | 手册截图重渲染 / 手册校验 |
| `make capture-image` / `make menu-shots` | 采集 Docker 镜像 / 全 ROM 菜单截图 |
| `make bump V=x.y.z` | 升版本号 |
| `make release-apk` / `make symbols` | 签名发布 APK（`dist/`）/ 上传原生符号 |
| `make release` / `make release-local` | 打 tag 走 CI 发布 / 本地 `gh` 发布 |

发布由 GitHub Actions（`.github/workflows`）执行：tag 推送后自动测试、构建并发布 Release。

## 五、架构要点小结

1. **三层模拟**：Compose UI（Kotlin）↔ JNI 桥接层（`app/src/main/cpp`）↔ 模拟核心（third_party 的 mGBA / melonDS）。
2. **数据驱动的游戏适配**：新游戏/新字段只需在 `gamedata/` 写 TOML 并重新生成，Android、3DS、Linux 三个平台共用同一份定义。
3. **伴侣即读内存**：通过 `NativeConfig` 描述每款游戏的结构，app 实时解码内存绘制 PARTY/BAG/BATTLE/MAP/DEX/GUIDE 等界面；游戏识别基于文件哈希，版本不匹配时给出 BEST EFFORT 降级或提示。
4. **质量保障闭环**：翻译检查、gamedata 新鲜度检查、单测（含真实 ROM 扩展）、Paparazzi 快照、Compose Desktop 压力测试、手册校验、网站测试，全部由 `make check` 串起并在 CI 强制通过。
5. **多平台共享**：3DS 与 Linux 移植复用 gamedata 生成的 C 配置与同一套伴侣逻辑。
